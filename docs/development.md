# Процесс разработки Golphi

## Ветки и этапы

Для каждой отдельной фичи создаётся feature-ветка от `develop` в существующем checkout. Git worktree не используется.

После каждого этапа проверяется результат, затем выполняются commit и push feature-ветки. По завершении работы создаётся итоговый PR. Целевая ветка PR — `develop` как рабочее допущение из design, а не отдельное согласованное требование пользователя.

## Работа с сабагентами

Для отдельных этапов используется навык Subagent Driven Development. Независимые задачи запускаются параллельно, если инструменты и зависимости позволяют.

При общем checkout координатор назначает агентам непересекающиеся файлы. Зависимые задачи и правки общих файлов выполняются последовательно. Переключение веток, интеграцию результатов, commit и push выполняет только координатор; Git-операции сериализуются и согласуются с работой агентов, чтобы не менять ветку во время их правок.

Если сабагенты недоступны или безопасный параллелизм невозможен, причина явно отмечается, а этап выполняется последовательно в том же checkout, без worktree.
