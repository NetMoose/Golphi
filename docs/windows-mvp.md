# Нативная проверка MVP на Windows

Целевой сеанс: Windows 11 Pro amd64, сборка 26100, масштаб 100%, обычный графический рабочий стол. Go, GTK и C-компилятор для готовых файлов не нужны. 28 октября 2026 года обе автоматические suites завершились с кодом 0, пользователь подтвердил PASS всех ручных шагов ниже. Журналы и итоговая приёмка сохранены в [отчёте MVP](mvp-validation.md). Ниже оставлена инструкция повторного запуска; Windows 10 этим запуском не проверяется.

## Автоматические проверки

Скопируйте в одну папку четыре файла из одного комплекта:

- `hello-windows-amd64.exe`;
- `golphi-ui.test.exe`;
- `golphi-win32.test.exe`;
- `verify-windows.ps1`.

Откройте обычный Windows PowerShell в этой папке и выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\verify-windows.ps1
$LASTEXITCODE
```

`Bypass` действует только для запускаемого процесса; глобально менять execution policy не нужно. Скрипт совместим с Windows PowerShell 5.1. Если скрипт лежит отдельно, укажите папку файлов параметром `-ArtifactDirectory 'C:\path\to\artifacts'`.

Будет создан `golphi-windows-mvp-<дата-время>.txt`: версия ОС, сборка, архитектура CPU через CIM, разрядность процесса, SHA256 всех трёх бинарников, полные stdout/stderr обеих тестовых программ и их коды завершения. Отдельные файлы `*.stdout.txt` / `*.stderr.txt` также сохраняются. Полный порядок между двумя потоками вывода не восстанавливается. Скрипт запускает все тесты без фильтра `-test.run`: UI с `GOLPHI_NATIVE_CORE=1`, затем весь backend Win32. Внутренний селектор `GOLPHI_RUN_TEST` и Linux-переключатель `GOLPHI_NATIVE_WM_CLOSE` очищаются; исходные значения окружения восстанавливаются после запуска.

На каждую программу задан `-test.timeout=90s` и внешний предел 120 секунд. При ошибке первой программы скрипт всё равно собирает вывод и запускает вторую; общий код будет ненулевым. Во время тестов могут кратко появляться окна. Не закрывайте их вручную. Нулевой общий код означает успех автоматических проверок, но не заменяет ручные шаги ниже.

## Ручная проверка общего примера

Из той же папки запустите:

```powershell
.\hello-windows-amd64.exe
$LASTEXITCODE
```

1. Проверьте заголовок «Golphi — приветствие», поле «Мир», кнопку «Поздороваться» и метку. Окно не должно растягиваться мышью или максимизироваться. Проверьте, что контролы видны и не перекрываются.
2. Введите `Иван`, нажмите кнопку: сразу «Привет, Иван! Работаю…», примерно через две секунды «Готово, Иван! Символов: 4». Кириллица должна отображаться без повреждения.
3. Во время ожидания печатайте в поле и перемещайте окно: интерфейс должен отвечать. Повторите нажатие с другим именем; старый результат не должен перезаписать новый.
4. После готовности закройте окно крестиком. Убедитесь, что процесс завершился и код равен 0.
5. Запустите **новый процесс** той же командой. Нажмите «Поздороваться» и закройте окно раньше двух секунд, пока worker ещё работает. Процесс должен завершиться без зависания; запишите код. Если worker успеет получить отказ передачи результата, диагностическая строка «Результат не передан в UI» допустима.

## Что прислать

Пришлите **весь файл `golphi-windows-mvp-*.txt`, даже при ошибке**, а не только последние строки. При проблемах приложите также отдельные stdout/stderr. Добавьте текст:

```text
ОС / сборка / архитектура:
Масштаб / тема:
Автотесты, общий код:
Кириллица и результат кнопки:
Отзывчивость во время worker:
Повторное нажатие с другим именем:
Фиксированный размер / расположение контролов:
Обычное закрытие, код:
Быстрое закрытие до 2 секунд, код:
Отклонения (или «нет»):
```

Снимок экрана нужен только при визуальном дефекте. Принятый Windows-прогон выполнен пользователем на целевой ОС; в Linux-среде подготовки этот комплект не запускался. Проверенный пример намеренно оставлен консольным. Для будущих GUI-сборок применяется `-ldflags="-H windowsgui"`; текущий комплект для приёмки не пересобирался.
