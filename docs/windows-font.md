# Системный шрифт Win32

На UI-потоке backend устанавливает системный DPI-контекст и определяет DPI запуска. Затем он запрашивает `NONCLIENTMETRICSW` через `SystemParametersInfoForDpi(SPI_GETNONCLIENTMETRICS, …, dpi)` и передаёт `lfMessageFont` в `CreateFontIndirectW`. Windows возвращает метрики для запрошенного DPI, поэтому Win32 backend использует их напрямую. Ошибка каждого из этих вызовов завершает запуск до открытия приёма Post. Манифест visual styles для получения шрифта не требуется. [SystemParametersInfoForDpi](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfofordpi) · [CreateFontIndirectW](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-createfontindirectw)

Driver владеет одним `HFONT` до завершения сессии. При создании Button, Edit и Label каждый новый HWND получает его через `WM_SETFONT` до показа. При прямом переносе того же HWND он сохраняет назначенный шрифт. Windows рисует заголовок формы, а Panel служит контейнером без собственного текста. Размеры и координаты задаются через `SetBounds`. Для кириллицы и других строк нужно предусмотреть достаточно места в заданных границах, поскольку назначение шрифта не увеличивает контроль. [WM_SETFONT](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-setfont)

Пока приложение работает, уничтожение отдельного контрола, detach и откат дерева освобождают свои HWND, а общий шрифт остаётся пригодным для существующих и новых контролов. При остановке driver сначала пытается уничтожить HWND. Стандартные контролы сами управляют своими DC, и driver не выбирает этот шрифт в DC. После выхода из цикла сообщений и уничтожения пользователей шрифта driver вызывает `DeleteObject` на UI-потоке. Если HWND с этим шрифтом пережил очистку, driver сохраняет `HFONT` и сообщает об ошибке. После успешного удаления handle очищается. [DeleteObject](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-deleteobject)

Ошибка или перехваченная паника отдельной операции очистки попадает в диагностику Run. Независимая очистка продолжается. Значение и стек первичной паники handler или Post сохраняются. Эта зависимость определяет порядок только для HWND и общего шрифта. Общая политика повторных попыток и судьба других неосвобождённых ресурсов остаются открытыми.
