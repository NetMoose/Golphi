# Проверка контракта E0 — define-component-contract

Дата: 27 октября 2026 года. Проверены документация и проектные примеры; библиотека и backend в этом изменении не реализованы.

## Результат

Согласованные контракты перенесены в [основной дизайн](../design.md), [пример жизненного цикла](component-lifecycle.md) и [пример событий](component-events.md). [Правила разработки](../development.md) сохраняют ветки от develop без worktree, commit/push после этапов, итоговый PR и Subagent Driven Development.

Независимые review подтвердили соответствие спецификациям и качество каждого документа. Итоговое review всей ветки также завершилось PASS без оставшихся замечаний. В ходе review исправлен порядок присоединения в эскизе: сначала панель к форме, затем кнопка к панели. Генераторная привязка приведена к SetOnClick; формат форм не утверждался заново.

## Проверки

- Все 7 сценариев component-lifecycle сопоставлены таблице ожидаемого состояния.
- Все 10 сценариев component-events сопоставлены трассировкам, включая отсоединённого предка и ограниченную область повторного OnChange.
- `openspec validate define-component-contract --strict` — успешно.
- `git diff --check` — без замечаний после замены пробельных переносов Markdown.
- Локальные ссылки документации существуют; Q-01–Q-14 и ADR-001–ADR-008 сохранены. Все ADR остаются Proposed; принятые решения выделены отдельно как D-01–D-06.

Это статическая сверка контрактов и документов. Компиляция эскизов, GUI, FFI, утечки ресурсов и критерии T-01–T-09 не проверялись и не объявляются выполненными.

## Открытые вопросы перед E1

Весь E0 не завершён. Сохраняется [полный реестр вопросов](../design.md#17-открытые-вопросы), в частности:

- зависимости и bridge, выбор первого Linux backend и baseline;
- bootstrap UI-потока, Run и Post;
- ошибки конструкторов и setters, доступ к уничтоженному объекту, повторный Destroy и panic;
- сигнатуры и источник событий, смена обработчика во время доставки, судьба ожидающего уведомления при смене обработчика/жизненного состояния;
- циклы и переносы иерархий, native lifecycle и механизм гарантированного отката SetParent;
- вопросы Q-07–Q-14, module path и совместимость лицензий зависимостей.

Ни один из этих вопросов не решён этим применением. Завершение задач данного изменения означает оформление согласованной части контракта, а не готовность runtime или закрытие E0.

## Организация работы

Примеры lifecycle и событий подготовлены параллельными агентами в разных файлах и прошли отдельные review. Изменения общего docs/design.md выполнены одним агентом; Git-операции выполнял только координатор. Worktree не создавался. Для OpenSpec-задач с checkbox-форматом задания агентам извлекались непосредственно из tasks.md: стандартный helper навыка ожидает заголовки Task N. Это техническая адаптация процесса, не изменение продуктового контракта.
