# Динамическое дерево: общий пример Linux и Windows

Исходник: [examples/dynamic-tree/main.go](../examples/dynamic-tree/main.go). Один публичный API, без платформенных ветвей и native-типов. Пример показывает вложенные Panel, создание детей в OnClick и Post, прямой перенос поддерева с Edit, отсоединение, тихую настройку, повторное присоединение и Destroy. Владельцем переносимой Panel остаётся Form; её Parent меняется между двумя панелями. Дети принадлежат переносимому дереву и уничтожаются вместе с ним.

## Сборка и запуск

Из корня репозитория, Linux amd64:

```sh
CGO_ENABLED=0 go build -o /tmp/golphi-dynamic-tree ./examples/dynamic-tree
/tmp/golphi-dynamic-tree
```

Нужен установленный GTK4 и сеанс X11. Сборка без C toolchain не означает отсутствие native runtime-библиотек. Окно использует фиксированную клиентскую область 1000×680 logical units; для ручной проверки она должна целиком помещаться на экране с выбранным масштабом.

Windows amd64, PowerShell:

```powershell
$env:CGO_ENABLED = '0'
go build -ldflags='-H windowsgui' -o dynamic-tree.exe ./examples/dynamic-tree
.\dynamic-tree.exe
```

Для cross-build на Linux:

```sh
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -ldflags='-H windowsgui' -o /tmp/golphi-dynamic-tree.exe ./examples/dynamic-tree
```

GUI EXE не открывает консоль. Ошибка операции отображается в строке состояния; диагностический stderr может быть недоступен при запуске из Explorer. Cross-build не является проверкой работы Windows.

## Ручной сценарий на каждой ОС

Проводить в настоящем desktop-сеансе, записав ОС, Go, GTK (Linux), масштаб/DPI и хеш бинарника. Кнопки и поля доступны обычной мышью и клавиатурой; программного API выделения пример не использует.

1. **Создание и вложенность.** При запуске поддерево находится слева. Счётчик OnChange равен нулю. Нажать обе кнопки создания ребёнка: появляются отдельные строки «OnClick» и «Post». Повтор заменяет свою строку, а не увеличивает дерево без ограничения. Вызов Post лишь принимает задачу; выполнение происходит позже в UI-потоке. Ввести текст в поле дерева: счётчик должен увеличиваться при реальных изменениях, без требования «один символ — одно событие» для IME/вставки.
2. **Clipping.** Во вложенной панели шириной 260 единиц метка начинается с x=180 и намеренно выходит вправо. Видна только начальная часть «Край: …»; окончание «ЭТОТ ХВОСТ СКРЫТ» не должно появляться за правой границей панели. Панель не должна расширяться ради метки. Повторить после переноса, reattach и создания заново. Проверить отсутствие перерисовочных артефактов после перекрытия окна другим окном.
3. **Прямой перенос с фокусом.** Ввести `АБ😀вгД`. Нажать «Перенести через 8 с», сразу вернуть фокус в Edit. Нажать Home, затем Shift+Right несколько раз, запомнить выделенную подстроку. Дождаться сообщения о переносе и появления дерева справа. Не щёлкая мышью, нажать Shift+Right: активный конец выделения должен продолжить движение с прежнего места, если backend сохранил native Edit. Затем набрать `X`: заменяется ожидаемая выделенная подстрока, ввод остаётся в Edit. Повторить справа налево, а также с End и Shift+Left для обратного направления и с одиночным курсором без выделения. Перед переносом текст и счётчик записать: сам перенос не должен менять текст или добавлять OnChange.
4. **Внешний фокус.** Снова запланировать перенос, за 8 секунд поставить курсор во внешнее поле сверху. После переноса печатать, не меняя фокус: изменяется внешнее поле. Перенос дерева не захватывает фокус.
5. **Detach/reattach без настройки.** Записать текст Edit и счётчик, нажать «Отсоединить поддерево»: всё дерево исчезает. Нажать «Присоединить через 8 с», поставить фокус во внешнее поле и дождаться появления дерева. Текст сохраняется, счётчик не растёт от detach/reattach, ввод продолжает идти во внешнее поле. Конкретный новый получатель фокуса сразу после detach не определяется.
6. **Тихая настройка.** Снова отсоединить дерево. Нажать «Тихая настройка…»: SetText и SetBounds выполняются только у отсоединённого Edit, счётчик не меняется. Можно создать обоих детей, пока дерево скрыто. Присоединить: видны подготовленные дети и текст `Тихо подготовлено: Я😀Б — новая база`, ширина поля немного уменьшена; счётчик остаётся прежним. Реальный ввод после присоединения снова вызывает OnChange. Курсор и выделение после пересоздания, включая detach/reattach, не входят в критерии этого этапа; конкретная позиция не обещается.
7. **Уничтожение.** Нажать «Уничтожить поддерево»: исчезают Edit, вложенная Panel и динамические дети. Кнопки операций сообщают, что нужно создать дерево заново. «Создать заново» возвращает новое дерево слева с исходным текстом; накопленный счётчик событий остаётся для наблюдения. Повторить цикл. Запланировать перенос и сразу уничтожить/создать дерево: старый отложенный callback не должен переносить новое дерево.
8. **Закрытие.** Закрыть окно системной кнопкой; процесс должен завершиться. Повторить закрытие с отсоединённым деревом, после уничтожения и до истечения 8 секунд отложенного переноса/reattach. Не должно оставаться зависшего процесса или появляться аварийное окно.

Новый отложенный перенос или reattach заменяет предыдущий; detach и Destroy отменяют ожидающую операцию. Во время восьмисекундной паузы UI продолжает обрабатывать ввод. Worker не читает компоненты: он только ждёт и вызывает Post. После закрытия очередь может отклонить Post или отменить принятую задачу; это допустимый исход.

Ручное поведение само по себе не доказывает идентичность native peer. Гарантию позиций из шага 3 относить к сохраняемому Edit только вместе с native-свидетельством этого пути backend. При пересоздании Edit проверяются текст и правила фокуса; сохранение курсора, выделения и активного конца при пересоздании отложено на следующий этап. Ошибки транзакций, rollback, pending/coalescing и точный однократный release проверяются отдельными автоматическими/native тестами, а не этим примером.

строки; [свидетельства](../artifacts/dynamic-example-feedback-20261113/observations.md).
