# Запуск общего примера MVP

`examples/hello` использует только публичный пакет `ui`: один исходный код для Linux и Windows, без платформенных импортов и ветвей. Форма содержит Edit, Button и Label с нативным оформлением ОС. Это экспериментальный статический MVP, а не универсальный layout engine.

Нужен Go версии из `go.mod` (сейчас 1.26.5). Все команды выполняются из корня репозитория. C-компилятор и CGo для сборки не нужны. При первом запуске Go может потребоваться доступ к сети для загрузки модулей.

## Linux

Нужны работающий графический сеанс и установленный GTK 4 runtime (`libgtk-4.so.1` с его зависимостями). Отсутствие C toolchain не отменяет эту зависимость времени исполнения. Проверка наличия GTK через кэш загрузчика, если доступен `ldconfig`:

```sh
ldconfig -p | rg 'libgtk-4\.so\.1'
```

Сборка и запуск:

```sh
CGO_ENABLED=0 go build -o /tmp/golphi-hello ./examples/hello
/tmp/golphi-hello
```

Запускайте бинарник из терминала в графическом сеансе, чтобы видеть ошибки загрузки GTK, запуска и завершения runtime.

## Windows (PowerShell)

Нужны Windows и графический сеанс. Используются системные Win32-контролы; GTK на Windows не требуется.

```powershell
$env:CGO_ENABLED = '0'
go build -o hello.exe ./examples/hello
if ($LASTEXITCODE -eq 0) { .\hello.exe }
```

Для проверки сборки Windows на Linux без запуска:

```sh
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -o /tmp/golphi-hello.exe ./examples/hello
```

Успех кросс-компиляции не заменяет проверку окна в Windows.

## Ручная проверка на каждой ОС

1. Запустите пример из терминала. Должна открыться форма «Golphi — приветствие» с полем «Мир», кнопкой «Поздороваться» и подсказкой. Клиентская область имеет размер 400 × 180 logical units без декораций. Проверьте, что окно не растягивается мышью и не максимизируется.
2. Проверьте расположение: Edit — `(16, 16, 368, 28)`, Button — `(16, 56, 160, 32)`, Label — `(16, 104, 368, 32)`. Координаты фиксированы относительно клиентской области; размеры контролов задают минимум. Нативная тема может увеличить контрол, поэтому снимок и фактические размеры следует зафиксировать отдельно. Автоматического устранения пересечений нет.
3. Введите `Иван` и нажмите кнопку. Сразу появится «Привет, Иван! Работаю…», примерно через две секунды — «Готово, Иван! Символов: 4». Кириллица должна оставаться целой в поле и метке. Подсчёт ведётся по Unicode code points, а не по байтам или графемам.
4. Во время ожидания продолжайте печатать и перемещать окно: интерфейс должен отвечать. Результат относится к имени в момент нажатия. Нажмите снова с другим именем: результат предыдущего запроса не должен перезаписывать новый. Пустое или состоящее из пробелов имя заменяется на «мир».
5. Закройте окно штатной кнопкой закрытия, в том числе во время ожидания. Процесс должен завершиться. Закрытие не ждёт фоновой goroutine; если она успеет получить отказ `ui.Post`, он выводится в stderr как «Результат не передан в UI». Ошибка `Run` выводится в stderr с префиксом «Golphi:» и кодом выхода 1.
6. Повторите запуск отдельным процессом и запишите ОС, масштаб экрана, тему, результат каждого шага и обнаруженные отклонения. Проверка одной ОС не подтверждает другую.

Все компоненты и статическая геометрия подготавливаются до `Form.Run()`. Один процесс допускает одну попытку запуска runtime на стартовом UI-потоке; повторное открытие примера выполняется новым процессом. Обработчик читает имя на UI-потоке, worker работает только со строкой, а изменение метки выполняется функцией `ui.Post`. `nil` от `Post` означает принятие задачи, а не гарантированное выполнение после закрытия окна.

Этот runbook описывает сценарий проверки; сам по себе он не подтверждает прохождение нативной приёмки Linux или Windows.
