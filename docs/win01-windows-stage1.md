# WIN-01: первый Windows-прогон — baseline и ресурсы

Это **подготовительный этап**, а не итоговая приёмка WIN-01. Backend пока не
назначает новый системный шрифт. Сначала нужно сохранить исходный вид приложения
и проверить генерацию встроенного манифеста на настоящей Windows.

## Что передаётся

Архив `artifacts/golphi-win01-stage1-windows-v2.zip` содержит исходники текущего
этапа, закреплённые зависимости инструмента, готовые `.syso`, baseline EXE,
PowerShell-скрипты и эту инструкцию. Распакуйте архив в отдельный каталог.
Baseline `artifacts/win01-baseline/hello-baseline.exe` построен до подключения
ресурсов и изменения шрифта из коммита `acc3afe51784cd1f75a4de248260ba442504aad1`.
SHA256 и команда сборки — в `artifacts/win01-baseline/build.txt`.

Для baseline достаточно Windows 11/amd64 и 64-битного Windows PowerShell 5.1.
Для генерации и сборки ресурсов дополнительно нужен **Go 1.26.5 windows/amd64**
в PATH; при первом запуске нужен доступ к Go modules. GCC, MinGW, Windows SDK
resource compiler и GUI headers не нужны. Генератор устанавливать отдельно
не требуется: он закреплён в `tools/winres/go.mod` и запускается через `go tool`.
Исходники с русскими PowerShell-сообщениями сохранены в UTF-8 с BOM.

## 1. Исходное оформление при 100%

Для этого этапа используйте основной монитор Windows и держите на нём форму
во время всех проверок и снимков; перенос между мониторами с разными DPI не
входит в объём. В параметрах Windows установите масштаб 100%. Если после изменения DPI окна
не обновился, выйдите и снова войдите в сеанс Windows. Откройте PowerShell
**в корне распакованного каталога**:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\capture-win01-baseline-windows.ps1 -Scale 100
```

Скрипт запустит baseline, проверит DPI **самого окна** (ожидается 96) и запишет
окружение и хеш. Оставьте исходный текст «Мир», расположите форму так, чтобы
её не перекрывали другие окна, и нажмите Enter в консоли. Скрипт сохранит PNG
области окна. Просмотрите PNG: захват экрана не убирает перекрывающие окна.

Проверьте ввод кириллицы, кнопку «Поздороваться», обновление результата через
две секунды. Вернитесь в консоль, введите `PASS` или `FAIL`, закройте форму
крестиком и подтвердите завершение. Скрипт не завершает чужие процессы.
При ошибке закройте оставшуюся форму вручную перед повторным запуском.

## 2. Исходное оформление при 150%

Завершите предыдущий процесс, установите масштаб 150% и выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\capture-win01-baseline-windows.ps1 -Scale 150
```

Повторите те же действия. Ожидается DPI окна 144. Скрипт отклоняет несовпадение
DPI: запуск с 96 DPI нельзя считать проверкой масштаба 150%.
Логи и PNG обоих прогонов сохраняются в `artifacts/win01-baseline-evidence`.
Скрипт использует стандартный .NET `Add-Type` для вызовов user32 и захвата
изображения; это не требует установки нативного C-компилятора.

## 3. Генерация и сборка на Windows

Оставаясь в корне распакованного каталога, проверьте Go и запустите:

```powershell
go version
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-win01-resources-windows.ps1
```

Скрипт временно устанавливает `CGO_ENABLED=0`, Windows/amd64, локальный toolchain,
readonly-модули и несуществующие CC/CXX; прежние значения окружения восстанавливает
на выходе. Он регенерирует ресурсы hello/dynamic-tree в отдельных каталогах результатов,
не изменяя переданные `.syso`, закреплённым go-winres,
сравнивает их SHA256 с переданными ресурсами, собирает GUI EXE и извлекает
встроенный XML для сравнения с исходником. Ненулевой код Go останавливает проверку.

По приглашению запустите `artifacts/win01-resource-evidence/hello-windows-amd64.exe`,
проверьте работу ввода/кнопки и закройте форму. Введите в консоли `PASS` или `FAIL`.
Не кладите `hello-windows-amd64.exe.manifest` рядом с EXE: манифест уже внутри.
Кнопка должна получить нативное тематизированное оформление; шрифт на этом
этапе ещё прежний. Полная проверка активации styles и нового HFONT будет
отдельным этапом, поэтому этот результат её не заменяет.

Логи сборки и извлечённые XML — в `artifacts/win01-resource-evidence`.
Подробнее о подключении к своему приложению: [ресурсы Windows](windows-resources.md).

## Что вернуть

Пришлите содержимое двух каталогов:

- `artifacts/win01-baseline-evidence` — два лога и PNG на 100%/150%;
- `artifacts/win01-resource-evidence` — лог генерации/сборки и извлечённые манифесты
  (передавать собранные EXE обратно не обязательно).

До получения этих результатов задачи 1.1 и 1.4 остаются открытыми. Новые
гарантии выделения пересозданного Edit, динамический DPI и остальные ранее
открытые вопросы этим прогоном не принимаются.

## Исправление запуска от 22 ноября

В первом архиве вычисление путей в значениях параметров по умолчанию могло
завершиться ошибкой `Join-Path`: `$PSScriptRoot` был пустым до выполнения тела
скрипта. В версии v2 пути вычисляются в теле обоих скриптов после обработки
параметров. Заданные явно `-Exe` и `-OutputDirectory` сохраняются. Baseline EXE
не пересобран: исходное оформление и его SHA256 остались прежними.

Распакуйте v2 в отдельный каталог и повторите первый запуск с `-Scale 100`,
затем продолжайте по этой инструкции. Можно также заменить только два `.ps1`
в старом каталоге файлами из v2. Исполнение в Windows всё ещё требует повторной
проверки; этот патч не является результатом native acceptance.
