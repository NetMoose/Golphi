# Внутренний контракт backend MVP

Это техническая граница MVP, не публичный интерфейс расширения. [Пробы GTK и Windows 11](mvp-validation.md) подтвердили FFI, callbacks и startup thread. Полный event loop и контролы ими не проверены. Открытые вопросы полной библиотеки сохраняются.

## Граница и поток

`internal/backend.Driver` использует только Go-типы: строки, непрозрачный `Peer`, `Bounds`, `Config`, `Event`, `Callbacks` и сохранённый `Panic`. Платформенные пакеты реализуют интерфейс; общий пакет их не импортирует. Выбор реализации выполняет вышележащая платформенная фабрика. Импорт backend не загружает native runtime.

Все методы, кроме `Wake`, вызываются на закреплённом UI-потоке. `Wake` допускается из любой goroutine. `Init(Callbacks)` сохраняет внутренние обработчики до `Close`. `Create(Config)` получает тип, текст, геометрию и ранее созданного родителя; нулевой родитель означает форму. Размер формы — клиентская область, координаты контролов — относительно её внутренней области. Перевод логических размеров и фиксация начального масштаба принадлежат backend.

`Peer` — ненулевой монотонный идентификатор внутри запуска, не HWND/GTK pointer/Go pointer; повторное использование запрещено. Backend хранит собственное отображение идентификаторов в handles. При отказе Create возвращает нулевой Peer и освобождает частично созданные ресурсы; ранее созданные peers очищает вызывающая сторона. Destroy сначала запрещает доставку и удаляет связь callback с peer, затем освобождает native-объект. При ошибке освобождения доставка не возобновляется; оставшиеся ресурсы учитываются для cleanup. Поздний callback не должен разрешаться в другой peer.

`SetText` может синхронно породить native-сигнал. Нормализация, объединение OnChange, выбор обработчика и подавление доставки до Running/после Stopping принадлежат ядру. `Change.Text` содержит скопированный снимок строки; Click и CloseRequest текста не требуют. CloseRequest означает немедленное начало обычной остановки. `Quit` только запрашивает выход, без уничтожения ресурсов.

## Строки и callbacks

На внутренней границе строки представлены UTF-8. Вопросы публичной валидации строк здесь не утверждаются. Для native-вызова GTK использует временный буфер UTF-8 с завершающим NUL, Win32 — UTF-16 с завершающим NUL и корректными surrogate pairs. Невалидный UTF-8/встроенный NUL должны обрабатываться согласованно на внутренней границе адаптеров, без молчаливого различающегося усечения; конкретная публичная политика остаётся вне задачи.

Временный буфер живёт до возврата native setter, который должен скопировать данные. Для API, сохраняющего указатель, требуется явно принадлежащая backend память до отключения native-потребителя. Полученные native-строки копируются в Go до окончания их срока жизни. Выделенную API память освобождают соответствующим allocator; borrowed GTK text не освобождают. Native-память не должна сохранять неукоренённый Go pointer.

Используется ограниченный набор ABI-совместимых trampolines и registry целочисленных ID; замена прикладного обработчика не создаёт новый FFI callback. Go closures удерживаются registry, native signal IDs и handles остаются внутри адаптера. Перед освобождением peer отключаются сигналы/связи. Registry и trampolines сохраняются, пока native-регистрации не сняты и callbacks не вернулись. Допустимое ограничением FFI удержание trampoline до конца процесса не должно удерживать объекты завершённого запуска.

Каждый вход native → Go оборачивает всю потенциально паникующую работу в `Capture`: сохраняются исходное значение и стек. Код после Capture только сохраняет результат, выставляет безопасное ABI-значение возврата и запрашивает выход без прикладной доставки. Адаптер сначала фиксирует failure-состояние, запрещающее новые события, затем синхронно вызывает `Callbacks.Failure`. Это внутренний непаникующий hook: немедленно закрыть очередь/прикладную доставку и записать диагностику; пользовательские функции в нём запрещены. Нельзя отложить остановку до возврата Run: иначе reentrant callback продолжит доставку после паники. Первый Panic также возвращается из Run; повторная запись одной первичной ошибки ядром не нужна. Никакая panic не должна пересечь FFI. Fatal runtime faults, os.Exit и Goexit не поддерживаются как прикладной control flow.

## Единая Go-очередь и пробуждение

`Queue` — единственная очередь Post. Она создаётся закрытой. `Open` вызывается после Init, подготовки peers и wake target, перед обычной доставкой. Stop необратим. Публичный ui.Post и process-wide Run admission реализуются следующими задачами.

Post никогда не вызывает функцию, в том числе на UI-потоке. Под одним mutex он проверяет допуск, вызывает Wake и добавляет задачу. Wake обязан быть неблокирующим, thread-safe, не вызывать dispatch inline и не обращаться обратно к Queue. Ошибка Wake отклоняет задачу без постановки; лишнее native-пробуждение при ошибке допустимо. Если UI уже получил уведомление до append, Dispatch ждёт тот же mutex и увидит принятую задачу. Успешный Wake гарантирует будущий безопасный turn loop, если остановка не началась. Допускается объединение native-уведомлений; теряемый hint без гарантии прогресса недостаточен.

Последовательно принятые задачи выполняются FIFO; вложенный Post добавляет в хвост. Dispatch подавляет вложенный dispatch. Ядро вызывает его только в безопасной точке loop вне прикладного/native event callback, включая вложенные циклы сообщений, вызванные setter. Выбор задачи под mutex — атомарная граница её начала: Stop отменяет ещё не выбранные, уже выбранная может завершиться. При panic Dispatch закрывает очередь, отменяет хвост и возвращает Panic. Для panic события то же закрытие делает Failure hook. Порядок относительно native events/OnChange, порядок конкурентных отправителей и fairness не определяются.

Stop использует admission mutex и ждёт текущий Wake. После возврата Stop native-пробуждение больше не может начаться. Последовательность cleanup: закрыть допуск, запросить Quit, выйти из активных callbacks/Run, попытаться уничтожить каждый peer, затем Close инфраструктуры. Wake target нельзя уничтожать раньше возврата Stop. Close также обязан освобождать частично созданную инфраструктуру после ошибки Init. Ошибка одной операции не отменяет независимые попытки очистки. Run сам ресурсы не уничтожает, а возвращает Panic и/или ошибку native loop для агрегирования ядром.

## Проверки и ограничения

`queue_test.go` проверяет настоящую общую очередь с fake асинхронного native wake: отсутствие inline-выполнения, FIFO/вложенность, закрытый допуск, nil, отмену, panic value/stack, отказ Wake, конкурентные Post/Dispatch/Stop и ожидание in-flight Wake перед teardown. Это проверка общего dispatch-контракта, не доказательство соответствия native-реализаций. Строки, handles, фактическое пробуждение, callback fencing и ошибки очистки должны дополнительно проверяться для каждого адаптера и реальной ОС. Публичный runtime этой задачей не реализован.

## Динамическое поддерево: внутренний контракт этапа 1.4

`Panel` добавлен к внутренним видам. Его дети используют внутреннюю область непосредственного родителя, обрезаются её границами и не увеличивают панель; layout, scrolling и оформление не добавляются. `Driver` расширен `PrepareTree(TreeChange)` и `SnapshotInput(Peer)`. Все новые типы — Go-данные, native handles остаются в адаптере. `UnsupportedTree`, пока встроенный в GTK/Win32, возвращает `ErrTreeUnsupported` без изменений и ресурсов попытки. Он **не реализует динамическое дерево**. Старый путь Create/Show/Run сохранён; текущий публичный runtime новый путь ещё не вызывает.

### Запрос, готовность и публикация

Ядро до вызова Driver проверяет поток, уничтожение, идентичность Parent, цикл, Owner-корень и цель. Для прежнего Parent операция остаётся no-op. До Run и для перехода неприсоединённое → неприсоединённое достаточно логического изменения; ядро не должно вызывать native-материализацию. Если последний переход передан внутреннему координатору, адаптер также не должен выделять peers.

`TreeChange.Nodes` — всё визуальное поддерево в порядке родитель перед ребёнком, с уникальными ненулевыми `NodeID`. Это корреляционные идентификаторы логических компонентов, не адреса и не peers. `Parent=0` только у корня; у потомков это ID предшествующего контейнера. `Peer` — прежняя материализация или ноль. `Target` — peer внешнего нового родителя, когда `ToAttached=true`, иначе ноль. Межформенный перенос не поддерживается. Адаптер не получает Owner-граф и не решает его правила.

| FromAttached → ToAttached | Native-обязанность | Публикация ядром после успеха |
|---|---|---|
| false → false | Без native-ресурсов | Только связи, тихая подготовка |
| false → true | Скрытая подготовка всего поддерева, свойства и ввод готовы | Полная таблица peers, новая база фактического текста |
| true → false | Удалить всё поддерево из интерфейса, сохранить позиции ввода | Обнулить bindings, отменить pending/накопление всех потомков |
| true → true | Перенести либо пересоздать всё поддерево с сохранением ввода | Сохранить pending/базу; не изображать detach/attach |

`PrepareTree` устанавливает fence прикладной доставки **до** native-действий, сохраняет прежнее размещение и весь затронутый ввод, удерживает необходимые для rollback старые peers. Допустимо частично подготовить попытку. При любой ошибке, требующей rollback/cleanup, возвращается ненулевая транзакция вместе с ошибкой; `nil,error` допустим только при гарантированном отсутствии изменений и работы, передаваемой вызывающей стороне. `nil,nil` — нарушение внутреннего контракта.

`ApplyTree` — небольшой общий координатор протокола, не реализация логического графа. После успешного Prepare он вызывает Commit. Commit возвращает полный `TreeResult` только после синхронной готовности каждого узла, фактического текста, фокуса и позиций. Массив bindings соответствует всем NodeID; у присоединённых узлов peer/generation ненулевые, у отсоединённых оба нулевые. Ввод Edit возвращается собственными Go-данными и сохраняется ядром при отсоединении. Буферы запроса заимствованы лишь на время операции; результат нельзя впоследствии менять через сохранённые адаптером slices/pointers.

Затем `publish` устанавливает целиком подготовленные логические связи, таблицы peer/generation и состояние событий. Это внутренний заранее подготовленный, непаникующий, безошибочный callback, без пользовательского кода и native-действий. После него `Finish` снимает временный fence и передаёт отложенное освобождение адаптеру. `Finish` не выполняет fallible release и не запускает прикладные callbacks. Транзакция одноразовая, вложенные транзакции запрещены; вызов SetParent из уже работающего прикладного обработчика разрешён. Внутри операции нельзя запускать Post dispatch или другие прикладные обработчики через вложенный loop.

После публикации нет шага, ошибка которого выдавалась бы за обычный SetParent error с обещанием старого Parent. Старые ресурсы уже успешного переноса остаются у адаптера до безопасного освобождения; его последующая диагностика относится к соответствующей cleanup-границе, а не к откату опубликованной операции. Политика дальнейших cleanup failures/retry остаётся открытой.

### Ввод и поколения native-сигналов

`InputState.Text` — фактический прочитанный UTF-8 текст. `Anchor` и `Caret` — границы выделения в Unicode scalar values, от 0 до числа scalar values включительно; одинаковые значения означают свёрнутое выделение. Это внутреннее представление, не публичный API курсора и не определение grapheme/IME поведения. Адаптер переводит GTK character offsets и Windows UTF-16 offsets, не разрезая surrogate pair. Недопустимое/непредставимое состояние нельзя молча обрезать: операция отказывает с восстановлением либо аварийным исходом. Матрица обратного выделения, IME, grapheme clusters и accessibility остаётся непроверенной; наличие Anchor/Caret само по себе её не закрывает.

`SnapshotInput` читает Edit без изменения. При переносе Prepare сам снимает свежий snapshot до мутаций: переданный кэш не заменяет реальное состояние присоединённого Edit. Отсутствие Input означает отсутствие ранее сохранённых позиций; после материализации адаптер возвращает фактический снимок. Кэш позиций применим только к соответствующему тексту; эффективный native readback обязателен. При прямом переносе нужно сохранить также фокус Button/другого узла внутри поддерева, а не только Edit: внутренний native-снимок транзакции включает общий focus target. Если фокус был снаружи, перенос его не забирает. Обычный rollback восстанавливает прежний ввод и внешний фокус. Detach сохраняет позиции, но нового получателя фокуса выбирает native-система; reattach не восстанавливает и не захватывает фокус. Реальное изменение отсоединённого текста сбрасывает selection и ставит caret в конец, равное присваивание сохраняет позиции; этот логический шаг принадлежит будущему ядру.

`Event.Generation` и `TreeBinding.Generation` задают внутренний epoch маршрутизации. Ноль зарезервирован старому статическому пути. При успешной динамической публикации поколения новые даже при сохранении того же Peer/native handle. Поколения не переиспользуются за запуск. Сигнал сохраняет токен эпохи своего происхождения; позднему сигналу нельзя присваивать «текущее» поколение по handle. Native registry/adapters должны отвергать старые и временные токены до вызова sink, ядро дополнительно сравнивает актуальные peer/generation. Сигналы создания, восстановления, setter и смены focus во время транзакции подавляются, а не откладываются для последующей доставки. Если toolkit доставляет их позднее, адаптер обязан идентифицировать происхождение и отбросить их. Одного булевого fence вокруг синхронного вызова недостаточно.

При rollback прежняя рабочая маршрутизация и pending ядра сохраняются, токены неуспешной попытки инвалидируются. При detach старое поколение отменено навсегда; reattach получает новое. При прямом переносе обновление native epoch не отменяет уже накопленные **логические** pending и базу сравнения. Адаптеры должны доказать это на реальных сигналах, включая одинаковый peer и пересоздание; текущий координатор этим не занимается.

### Отказ, освобождение и пределы доказательств

При ошибке Prepare или Commit координатор вызывает Rollback. `nil` означает восстановленное прежнее работоспособное состояние всего приложения, включая ввод; ошибки освобождения ресурсов попытки сюда не входят. Ошибка Rollback означает аварийный исход и должна заранее защёлкнуть запрет native-доставки в адаптере. Координатор вызывает внутренний `fatal(*TreeFailure)` **до** cleanup: ядро синхронно закрывает Post/доставку, отменяет pending, сохраняет указатель диагностики. `Finish` не снимает аварийный запрет. Текущий callback может закончиться, окончательный teardown ждёт выхода из него. Сочетания последующей паники/операций текущего обработчика не получают новых обещаний.

`TreeFailure` хранит исходную Cause, Restore и независимые CleanupFailure, поддерживает обход errors.Is. Fatal определяется невозможностью восстановления, а не cleanup error. CleanupStep выполняются независимо; panic каждой операции сохраняет исходное значение и стек через Capture, следующая попытка всё равно выполняется. Список cleanup дополняется после fatal hook, поэтому hook сохраняет указатель, а не преждевременную копию. Это внутреннее устройство диагностики, не утверждённый публичный тип ошибки. Cleanup при обычном отказе не вызывает общий stop.

Адаптер владеет частичными peers, retired peers, native registrations и callback roots; ядро владеет опубликованными логическими bindings. Удаление маршрута не разрешает освобождать память активного callback. CleanupStep может освобождать только уже безопасные независимые ресурсы; остальное остаётся в явном реестре адаптера до безопасного loop turn/выхода из callback либо финального Close. Неудачная release также остаётся учтённой. Отключение сигналов предшествует освобождению roots; не требуется и не разрешается преждевременный free ради завершения транзакции. Прежние требования Capture, Stop/Wake, Destroy и Close сохраняются. Успешное освобождение всех ресурсов и новая retry-политика не обещаются.

`tree_test.go` проверяет настоящий ApplyTree с fake native-операциями: успешный commit до публикации под fence, отсутствие публикации при Prepare/Commit error, rollback, ранний fatal hook, независимую cleanup после error/panic со стеком, сохранение совокупной диагностики и отказ unsupported. Fake передаёт Unicode-снимок без потерь; это **не** проверка native-перевода индексов, реального фокуса, Panel clipping, подавления поздних сигналов или безопасного освобождения callback roots.

Обе [технические native-пробы](dynamic-tree-validation.md) прошли в своей ограниченной матрице. GTK-пауза 150 мс — эксперимент, не production-протокол. Контракт требует синхронной готовности без произвольного sleep и ожидания paint; будущие задачи адаптеров 4.x должны доказать событийное завершение восстановления внутри этого контракта либо сообщить blocker. Ни декларации Driver, ни fake, ни cross-build Windows не являются таким доказательством.

### Подготовленные позиции при startup (этап 3.4)

`Config.Input` — необязательный собственный снимок подготовленных позиций Edit
для `Config.Text`, передаваемый ядром при первом `Create`. Как и `TreeNode.Input`,
он использует Unicode scalar offsets; `Focused=false` не задаёт новый контракт
начального фокуса и не запрашивает его захват. При отсутствии снимка сохраняется
обычное начальное поведение backend. Реальное SetText логически подготовленного
Edit задаёт конец нового текста; равное присваивание сохраняет позиции.
Текущий shared fake применяет поле, GTK/Win32 пока сохраняют старый статический
путь и начнут применять подготовленные позиции в задачах адаптеров 4.x.
