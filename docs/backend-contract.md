# Внутренний контракт backend MVP

Это техническая граница MVP, не публичный интерфейс расширения. [Пробы GTK и Windows 11](mvp-validation.md) подтвердили FFI, callbacks и startup thread. Полный event loop и контролы ими не проверены. Открытые вопросы полной библиотеки сохраняются.

## Граница и поток

`internal/backend.Driver` использует только Go-типы: строки, непрозрачный `Peer`, `Bounds`, `Config`, `Event`, `Callbacks` и сохранённый `Panic`. Платформенные пакеты реализуют интерфейс; общий пакет их не импортирует. Выбор реализации выполняет вышележащая платформенная фабрика. Импорт backend не загружает native runtime.

Все методы, кроме `Wake`, вызываются на закреплённом UI-потоке. `Wake` допускается из любой goroutine. `Init(Callbacks)` сохраняет внутренние обработчики до `Close`. `Create(Config)` получает тип, текст, геометрию и ранее созданного родителя; нулевой родитель означает форму. Размер формы — клиентская область, координаты контролов — относительно её внутренней области. Перевод логических размеров и фиксация начального масштаба принадлежат backend.

`Peer` — ненулевой монотонный идентификатор внутри запуска, не HWND/GTK pointer/Go pointer; повторное использование запрещено. Backend хранит собственное отображение идентификаторов в handles. При отказе Create возвращает нулевой Peer и освобождает частично созданные ресурсы; ранее созданные peers очищает вызывающая сторона. Destroy сначала запрещает доставку и удаляет связь callback с peer, затем освобождает native-объект. При ошибке освобождения доставка не возобновляется; оставшиеся ресурсы учитываются для cleanup. Поздний callback не должен разрешаться в другой peer.

`SetText` может синхронно породить native-сигнал. Нормализация, объединение OnChange, выбор обработчика и подавление доставки до Running/после Stopping принадлежат ядру. `Change.Text` содержит скопированный снимок строки; Click и CloseRequest текста не требуют. CloseRequest означает немедленное начало обычной остановки. `Quit` только запрашивает выход, без уничтожения ресурсов.

## Строки и callbacks

На внутренней границе строки представлены UTF-8. Вопросы публичной валидации строк здесь не утверждаются. Для native-вызова GTK использует временный буфер UTF-8 с завершающим NUL, Win32 — UTF-16 с завершающим NUL и корректными surrogate pairs. Невалидный UTF-8/встроенный NUL должны обрабатываться согласованно на внутренней границе адаптеров, без молчаливого различающегося усечения; конкретная публичная политика остаётся вне задачи.

Временный буфер живёт до возврата native setter, который должен скопировать данные. Для API, сохраняющего указатель, требуется явно принадлежащая backend память до отключения native-потребителя. Полученные native-строки копируются в Go до окончания их срока жизни. Выделенную API память освобождают соответствующим allocator; borrowed GTK text не освобождают. Native-память не должна сохранять неукоренённый Go pointer.

Используется ограниченный набор ABI-совместимых trampolines и registry целочисленных ID; замена прикладного обработчика не создаёт новый FFI callback. Go closures удерживаются registry, native signal IDs и handles остаются внутри адаптера. Перед освобождением peer отключаются сигналы/связи. Registry и trampolines сохраняются, пока native-регистрации не сняты и callbacks не вернулись. Допустимое ограничением FFI удержание trampoline до конца процесса не должно удерживать объекты завершённого запуска.

Каждый вход native → Go оборачивает всю потенциально паникующую работу в `Capture`: сохраняются исходное значение и стек. Код после Capture только сохраняет результат, выставляет безопасное ABI-значение возврата и запрашивает выход без прикладной доставки. Адаптер сначала фиксирует failure-состояние, запрещающее новые события, затем синхронно вызывает `Callbacks.Failure`. Это внутренний непаникующий hook: немедленно закрыть очередь/прикладную доставку и записать диагностику; пользовательские функции в нём запрещены. Нельзя отложить остановку до возврата Run: иначе reentrant callback продолжит доставку после паники. Первый Panic также возвращается из Run; повторная запись одной первичной ошибки ядром не нужна. Никакая panic не должна пересечь FFI. Fatal runtime faults, os.Exit и Goexit не поддерживаются как прикладной control flow.

## Единая Go-очередь и пробуждение

`Queue` — единственная очередь Post. Она создаётся закрытой. `Open` вызывается после Init, подготовки peers и wake target, перед обычной доставкой. Stop необратим. Публичный ui.Post и process-wide Run admission реализуются следующими задачами.

Post никогда не вызывает функцию, в том числе на UI-потоке. Под одним mutex он проверяет допуск, вызывает Wake и добавляет задачу. Wake обязан быть неблокирующим, thread-safe, не вызывать dispatch inline и не обращаться обратно к Queue. Ошибка Wake отклоняет задачу без постановки; лишнее native-пробуждение при ошибке допустимо. Если UI уже получил уведомление до append, Dispatch ждёт тот же mutex и увидит принятую задачу. Успешный Wake гарантирует будущий безопасный turn loop, если остановка не началась. Допускается объединение native-уведомлений; теряемый hint без гарантии прогресса недостаточен.

Последовательно принятые задачи выполняются FIFO; вложенный Post добавляет в хвост. Dispatch подавляет вложенный dispatch. Ядро вызывает его только в безопасной точке loop вне прикладного/native event callback, включая вложенные циклы сообщений, вызванные setter. Выбор задачи под mutex — атомарная граница её начала: Stop отменяет ещё не выбранные, уже выбранная может завершиться. При panic Dispatch закрывает очередь, отменяет хвост и возвращает Panic. Для panic события то же закрытие делает Failure hook. Порядок относительно native events/OnChange, порядок конкурентных отправителей и fairness не определяются.

Stop использует admission mutex и ждёт текущий Wake. После возврата Stop native-пробуждение больше не может начаться. Последовательность cleanup: закрыть допуск, запросить Quit, выйти из активных callbacks/Run, попытаться уничтожить каждый peer, затем Close инфраструктуры. Wake target нельзя уничтожать раньше возврата Stop. Close также обязан освобождать частично созданную инфраструктуру после ошибки Init. Ошибка одной операции не отменяет независимые попытки очистки. Run сам ресурсы не уничтожает, а возвращает Panic и/или ошибку native loop для агрегирования ядром.

## Проверки и ограничения

`queue_test.go` проверяет настоящую общую очередь с fake асинхронного native wake: отсутствие inline-выполнения, FIFO/вложенность, закрытый допуск, nil, отмену, panic value/stack, отказ Wake, конкурентные Post/Dispatch/Stop и ожидание in-flight Wake перед teardown. Это проверка общего dispatch-контракта, не доказательство соответствия native-реализаций. Строки, handles, фактическое пробуждение, callback fencing и ошибки очистки должны дополнительно проверяться для каждого адаптера и реальной ОС. Публичный runtime этой задачей не реализован.
