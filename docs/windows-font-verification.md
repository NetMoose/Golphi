# WIN-01: проверка шрифта и оформления на Windows

Первый ресурсный этап уже принят: baseline при 96/144 DPI и генерация/сборка
манифестов на Windows подтверждены. Повторять старую подготовку не нужно.
Этот пакет проверяет новый системный шрифт и его время жизни, actual visual
styles, геометрию примера и регрессии динамического дерева.

## Подготовка

Распакуйте `artifacts/golphi-win01-font-windows.zip` в отдельный каталог.
Нужна Windows 11/amd64, 64-битный PowerShell 5.1, интерактивный рабочий стол
с включёнными visual styles. Go и генератор для этого готового пакета не нужны.
Исходники `.ps1` сохранены в UTF-8 с BOM. Не переносите рядом с EXE сторонние
`.manifest` из старых проверок: тестовые манифесты встроены в EXE.

Работайте на основном мониторе, без параллельных GUI-тестов. Сначала установите
масштаб 100%, завершите старые экземпляры Golphi и откройте PowerShell в корне
распакованного каталога. Если Windows сохраняет прежний системный DPI после
изменения масштаба, выйдите и снова войдите в сеанс перед запуском.

## Два запуска

При 100%:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-win01-font-windows.ps1 -Scale 100
```

Закройте приложения, установите 150% и повторите отдельным процессом:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-win01-font-windows.ps1 -Scale 150
```

Скрипт задаёт ожидаемый DPI 96 или 144; нативный тест сравнивает его с DPI
реального backend, а не только с введённым аргументом. Если сравнение не прошло,
такой запуск не считается проверкой нужного масштаба.

## Автоматическая часть

Для каждого масштаба скрипт выполняет:

1. `TestWindowsFont*` в **консольном тестовом EXE без манифеста** — системный
   шрифт не зависит от включения visual styles.
2. Те же тесты в **консольном тестовом EXE со встроенным манифестом** — проверка
   метрик, HFONT, контроля активации styles, создания/пересоздания/переноса,
   очистки и ошибочных путей. Манифест добавлен только к копии тестового EXE;
   библиотека не содержит скрытого манифеста.
3. Три существующие backend-проверки: dynamic tree, retained HWND transfer,
   aborted cleanup.
4. Публичный `TestStartupFailure` и native UI-интеграцию динамического дерева.

Windows может ненадолго показывать тестовые окна. Не закрывайте их вручную и
не переключайте фокус во время автоматической части. Ненулевой exit code, SKIP
или отсутствие PASS останавливают сценарий. Скрипт записывает реальные SHA256
каждого EXE и возвращает изменённые переменные окружения после завершения.
Тесты паник должны завершаться PASS после штатной проверки диагностики; это
не означает, что ошибки были проигнорированы.

## Ручная часть

После автоматических проверок скрипт сам последовательно откроет два GUI-примера.
Вспомогательный `capture-win01-window-windows.ps1` считывает DPI каждого реального
окна через `GetDpiForWindow`, проверяет 96/144 и записывает SHA256 его EXE.
Разместите форму на основном мониторе и уберите перекрывающие окна перед Enter:
снимок копирует реальные экранные пиксели, не убирая перекрытия.

Сначала откроется `hello.exe`. Оставьте исходный текст «Мир» и снимите форму
по приглашению. Сравнивайте `hello-after-100-*.png` с сохранённым
[baseline 100%](../artifacts/win01-stage1-windows-20261122/baseline-100.png),
а `hello-after-150-*.png` — с
[baseline 150%](../artifacts/win01-stage1-windows-20261122/baseline-150.png).
Это один и тот же исходный пример с прежними Bounds; сравниваются шрифт,
читаемость текста и нативное оформление кнопки при одном DPI. После снимка
проверьте кнопку и ввод, отметьте PASS/FAIL и закройте форму.

Затем откроется `windows-appearance.exe`. Выполните пункты
[инструкции примера](windows-appearance-example.md): достаточные размеры,
верхние/нижние элементы кириллицы, длинный ввод, намеренно тесные границы и
вложенный clipping, добавление/скрытие/возврат подписи. Сделайте снимок по
приглашению, отметьте PASS/FAIL и закройте форму. У этого нового примера нет
старого baseline: он проверяет граничные случаи, а не служит парой «до/после».
Снимки и capture-журналы сохраняются автоматически в каталог результатов.

Последним откройте `dynamic-tree.exe` по полному пути, напечатанному скриптом.
Проверьте прямой перенос сохраняемого поля:

1. Нажмите «Перенести через 8 с» и сразу верните фокус в переносимое поле.
2. Дождитесь переноса с обычным курсором; введите текст без повторного щелчка.
3. Повторите перенос с прямым и обратным выделением через Shift+стрелки.
4. Отдельно повторите с Shift+Home и Shift+End, в том числе с выделением до
   конца строки. Выделение и его активный конец должны сохраниться после
   прямого переноса; ввод должен работать без нового щелчка.

Отметьте результат в консоли. Дополнительные пояснения — в
[инструкции динамического примера](dynamic-tree-example.md).
**Позиции после пересоздания Edit всё ещё не гарантируются**; для прямого
retained-переноса прежние гарантии сохраняются.

GUI-примеры собираются с `-H windowsgui` и не открывают консоль. Консольные
тестовые EXE нужны для журналов. Ручные ответы не подменяют автоматические
проверки styles/HFONT, а автоматические PASS не подменяют осмотр clipping.

## Что вернуть

Пришлите весь `artifacts/win01-font-evidence`: итоговые и автоматические журналы,
capture-журналы и по два PNG на каждом масштабе. При FAIL приложите созданные логи,
даже если сценарий остановился до ручной части. Не требуется повторная передача
EXE. Первый ресурсный этап остаётся принятым независимо от исхода этого нового
прогона. Остальные открытые вопросы WIN-01 и библиотеки не закрываются.
