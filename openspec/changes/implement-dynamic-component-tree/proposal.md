# Proposal

## Why

Принятый native UI MVP поддерживает только статическое дерево одной формы. Чтобы проверить компонентную модель за пределами этого среза, нужны вложенные панели и безопасное изменение дерева во время работы с сохранением событий и состояния ввода.

## What Changes

- Добавить минимальную Panel, вложенность и clipping, без layout, прокрутки и оформления.
- **BREAKING**: обобщить экспериментальные Owner/Parent с *Form до ролей Component/Container. Owner обязателен и неизменяем на этом этапе, кроме корневой формы; возможность пересмотра в будущем сохранена.
- Разрешить логическое создание во время Run и синхронное атомарное присоединение поддерева без ожидания paint, в пределах одной формы по цепочке Owner.
- Разрешить SetBounds неприсоединённых контролов после запуска; сохранить ограничения геометрии присоединённых контролов и SetClientSize.
- Определить отмену/сохранение уведомлений и сброс базы при изменении присоединённости; сохранить фокус, курсор и выделение при прямом переносе.
- Определить ошибки проверок, очистку неудачной попытки и аварийную остановку при невозможности восстановить прежнее нативное состояние.
- Проверить обе реализации на принятой Linux/X11 и Windows 11 матрице, включая native-перенос, clipping и восстановление ввода.

## Capabilities

### New Capabilities

Нет: расширяются существующие границы контрактов.

### Modified Capabilities

- `component-lifecycle`: роли, Panel, динамическое дерево, атомарность, геометрия, состояние ввода и проверки.
- `component-events`: тихая материализация, переходы присоединённости и база сравнения при повторном присоединении.
- `application-failure`: диагностика неудачной операции и аварийный исход невозможного восстановления.
- `native-ui-runtime`: проверка UI-потока динамических операций во время работы.
- `post-dispatch`: закрытие приёма и отмена задач при аварийном отказе восстановления дерева.

## Impact

Затрагиваются ui/components.go, geometry.go, events.go, run.go, внутренний Driver и оба backend, fake/native tests, примеры и документация. Текущий Driver не имеет Panel, переноса и снимка состояния ввода; расширение требует отдельного технического прохода до зависимых работ. Native-типы не выходят в публичный API. Собственный C bridge и новые зависимости не предлагаются.

Одна работающая форма, один Run, Win32/GTK4 и прежняя политика Post сохраняются. Несколько окон/межформенные переносы, смена Owner, изменение геометрии присоединённых контролов, layout и остальные открытые вопросы не входят. Это предложение, не начало реализации; apply выполняется по отдельному запросу.

Разработка: отдельная ветка от актуальной develop, без worktree, Subagent Driven Development и параллельные независимые задачи при возможности; review, commit/push по этапам, итоговый PR в develop. Git выполняет координатор.
