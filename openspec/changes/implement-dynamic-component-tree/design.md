# Design

## Context

Мотивация — proposal.md, Why. Исходная точка: принятый и архивированный implement-native-ui-mvp, develop после PR #10. ui/components.go хранит owner/parent как *Form, запрещает создание и SetParent при runActive. geometry.go запрещает настройку по started, даже после отсоединения. events.go проверяет непосредственного Parent, что недостаточно для вложенных панелей. run.go содержит таблицы component↔peer, одноразовый startup и общий сбор failures, вызывающий остановку; обычную ошибку операции нельзя безусловно добавлять в этот список.

Driver сейчас поддерживает Form/Edit/Button/Label, Create/Destroy/Text/Show и loop, но не перенос, скрытую подготовку транзакции, Panel или снимок ввода. В backend имеются native-сигналы и registry, поэтому изменение дерева внутри callback требует подавления технических сигналов, безопасной смены маршрутизации и отсроченного освобождения. GTK и Win32 могут нормализовать текст по-разному; новое сравнение и восстановление выделения должны опираться на действительное состояние поля.

Матрица остаётся прежней: Linux Mint 22.3 amd64 X11 GTK 4.14.5, Windows 11 Pro amd64 build 26100 / 100% / 96 DPI; Go 1.26.5, purego v0.11.2, CGO_ENABLED=0 для приложения. Windows native-проверку нельзя заменить cross-build.

## Goals / Non-Goals

**Goals:** согласованные дельты lifecycle/events/failure/runtime/Post; наблюдаемая целостность поддерева, корректность callbacks, переносимость состояния ввода и диагностика отказов.

**Non-Goals:** несколько работающих форм и перенос между формами; SetOwner, обычные компоненты без Owner, геометрия присоединённых контролов после Run, изменение клиентского размера после Run, layout/resizing/DPI switching, scrolling/оформление Panel, новые события фокуса, публичный API курсора/выделения, публичный Application, стабильный API сторонних компонентов. Все ранее открытые вопросы сохраняются, кроме явно согласованных здесь частей. Паника обработчика, one-shot Run, normal close и FIFO Post не переопределяются.

## Decisions

### Общие роли вместо списка типов

Принято: Owner — Component, Parent — Container; Form/Panel выполняют обе роли. Предлагаемый способ реализации — Go-интерфейсы с внутренней идентичностью компонента и закрытым маркером контейнера, а не публичная встраиваемая база. Это позволяет общие сигнатуры без обещания поддержки произвольной сторонней реализации. Конкретный состав интерфейсов — техническая деталь, не новый контракт расширяемости. Нельзя автоматически делать любой Component контейнером.

Конструкторы принимают Component, SetParent — Container. Пустой Owner включает typed-nil в интерфейсе: его нельзя принять как живого владельца. Логическая идентичность, а не адрес native peer, определяет Owner/Parent и no-op. Owner фиксируется при создании; существующий живой владелец исключает создание циклов Owner без операции смены владельца. Циклы Parent проверяются отдельно. Корень формы определяется по Owner даже у полностью отсоединённого дерева. Возможность пересмотра обязательности и неизменяемости Owner в будущем явно сохранена.

### Логическая подготовка и синхронная транзакция

Принято: создание всегда логическое, native-материализация — при успешном SetParent к работающей форме, либо в Run для заранее собранного дерева. Конструктор с native-созданием отклонён: он мешал бы тихой подготовке и потребовал бы нового места возврата native-ошибки. Асинхронный SetParent отклонён: после nil всё поддерево уже должно быть готово, хотя paint не ожидается.

Предлагаемый алгоритм: проверить получателя/поток/цель и цикл; вычислить Owner-корень и старую/новую присоединённость; сохранить связи, события и состояние ввода; подготовить необходимую native-операцию с подавлением прикладной доставки; после успеха зафиксировать новое размещение и таблицы peer; при отказе восстановить прежнее и собрать диагностику очистки. Старые peer нельзя преждевременно уничтожать, если они нужны для отката. Native-reparent или пересоздание допустимы только при выполнении одинаковых гарантий. Сбой восстановления состояния ввода также может нарушить гарантию, а не только отказ назначения native-parent.

Не обещаем невидимость промежуточных paint на уровне оконной системы: гарантии касаются итогового состояния, сохранения прежней работоспособности при обычном error и отсутствия прикладных callback внутри незавершённого SetParent. Нельзя выдавать частично присоединённое поддерево как успешный результат.

### Четыре перехода присоединённости

Присоединённость определяется всей цепочкой Parent до формы; доставку дополнительно ограничивает running. Для дерева до Run native-создания нет.

| До → после | Действие и события во время Running |
|---|---|
| Нет → нет | Только логические связи; подготовка тихая |
| Нет → да | Материализовать поддерево, тихо применить свойства; новая база текста |
| Да → нет | Убрать из интерфейса, отменить pending и накопление всех потомков; сохранить логическое дерево |
| Да → да | Прямой перенос; сохранить pending и базу, не имитировать логическое отсоединение |

SetParent с тем же Parent, включая nil, ничего не меняет после необходимых guards. Ошибка обычного отката не меняет состояние событий. Отменённое поколение уведомлений не может ожить после reattach. Внутри OnChange последовательность А → detach → тихое Б → attach → А даёт одно повторное уведомление после выхода; attach без дальнейшего изменения — ни одного. Замена/nil обработчика, уничтожение и coalescing сохраняют прежние контракты.

### Геометрия и ввод

Panel использует внутреннюю область как начало координат детей, обрезает выходящие части и не растёт ради них. На GTK нельзя считать GtkFixed автоматически обеспечивающим требуемый clipping — это проверяется native-тестом. Минимальные размеры темы сохраняются. SetBounds разрешён после Run у неприсоединённых контролов независимо от started, включая ранее отображённые; SetClientSize остаётся только до Run. Для присоединённых контролов динамическая геометрия не добавляется.

Снимок ввода должен сохранять фокус, курсор и диапазон выделения Edit независимо от возможности смены peer. Перевод native-позиций проверяется кириллицей и символами вне BMP: индексы UTF-16 и GTK не следует считать одинаковыми. Внешний фокус переносом не захватывается. Явное отсоединение сохраняет позиции при неизменном тексте, но не обещает возврат фокуса; выбор новой цели оставлен native-системе. Реальное SetText отсоединённого Edit сбрасывает выделение и ставит курсор в конец; равный текст сохраняет позиции. Публичные методы управления выделением не вводятся ради тестирования — используются внутренние hooks/native-проверки.

### Обычная ошибка и аварийный отказ

Принятое уточнение Transactional parent assignment — явное исключение, а не молчаливое ослабление старого контракта. Если прежнее состояние сохранено, SetParent возвращает исходную ошибку и сбои очистки попытки, приложение продолжает работу. Cleanup panic перехватывается по операции со стеком, независимая очистка продолжается. Отдельный список диагностики операции не должен сам переводить весь runtime в stopping.

Если прежнее работоспособное состояние восстановить невозможно, закрываются Post и доставка, ожидающее отменяется; SetParent возвращает error, текущий вызов может закончиться, окончательная очистка выполняется после callback. Run возвращает исходную ошибку, ошибки восстановления и очистки без выдуманной первичной паники. Внутренний носитель ошибки может различать recoverable/fatal, но стабильный публичный тип и способ различения не утверждаются. Необходимые для безопасности callback roots нельзя освобождать так, чтобы запоздалый native callback попадал в освобождённую память.

Для первого присоединения действует то же разделение. При обычной ошибке с сохранённым прежним состоянием Parent остаётся nil, подготовленное поддерево сохраняется и присоединение можно повторить. Если восстановить прежнее работоспособное нативное состояние приложения невозможно, применяется аварийный исход: повторная попытка в этой сессии не гарантируется. Сбой очистки ресурса попытки сам по себе не означает невозможность восстановления — при сохранённом прежнем состоянии действует обычный возврат ошибки с диагностикой.

### Поток и границы текущего этапа

Во время работы конструкторы обычных компонентов, SetParent и SetBounds требуют UI-поток даже для отсоединённых объектов. Проверки выполняются до изменений/native-вызовов; уничтоженный получатель проверяется первым. Для повторного Parent запрет фонового вызова сохраняется. Фоновая panic не превращается автоматически в ошибку Run; тест перехватывает её в той goroutine, где она возникла. Общий контракт потоков всех остальных API этим не расширяется.

## Risks / Trade-offs

- GTK/Win32 не позволяют одинаковый простой reparent → сначала ограниченный native-эксперимент обоих backend: вложенность/clipping, snapshot/restore ввода, prepare/rollback и callback-safety; затем узкий Driver. Если гарантия неосуществима, сообщить blocker, не ослаблять её молча.
- Потеря текста/выделения при пересоздании → readback, Unicode-тесты и проверки success/failure/reattach.
- Скрытый reentrancy из native-сигнала → блокировать прикладную доставку до commit, generation tokens и тесты запоздалых сигналов.
- Неудачная cleanup может оставить ресурс → сохранить диагностику и безопасность callback; политика retry/судьба неосвобождённых ресурсов остаётся открытой, успешное освобождение всех ресурсов не обещается.
- Разные Owner/Parent обходятся несколько раз → единый набор логически уничтоженных объектов и подсчёт native-release, особенно при уничтожении из дочернего callback.

## Migration Plan

1. На apply создать ветку от актуальной develop без worktree. Дизайн задаёт этапы; применить Subagent Driven Development, независимые native-эксперименты/адаптеры параллельны после фиксации интерфейса, Git только координатор.
2. Сохранить работоспособность прежнего examples/hello и его API-вызовов; типизированные переменные *Form у Owner()/Parent() потребуют перехода к ролям. API остаётся экспериментальным.
3. Сначала native-проверки технического пути, затем граф/транзакции/events, интеграция адаптеров, fault-injection и общий динамический пример. Review и commit/push после каждого этапа.
4. Прогнать старые и новые автоматические проверки, native и ручные сценарии обеих ОС. Будущие Windows GUI-примеры собирать с -ldflags="-H windowsgui"; тестовые EXE остаются консольными. Старые переданные артефакты не переписывать.
5. Обновить текущую документацию и Scope с точной границей принятых решений. Sync/archive — отдельный запрос после выполнения и PR. Основные specs сейчас не редактируются.

## Open Questions

Не закрываются: несколько окон и перенос между формами; изменение Owner и создание обычных компонентов без него в будущем; layout/resizing, динамическая геометрия присоединённых компонентов, DPI/другие платформы; публичный Application и сторонние компоненты; публичный API курсора/выделения и SetText присоединённого поля; прочие события и Program/User; порядок Post/native/OnChange, fairness, перегрузка, ожидание/индивидуальная отмена Post; стабильная диагностика и различение обычных/аварийных ошибок; зависимая очистка, retry, неосвобождённые ресурсы, зависания/тайм-ауты; сочетание новой аварийной причины с последующей паникой текущего обработчика, дополнительные операции после fatal SetParent до выхода из callback; самостоятельный Destroy и другие внутренние сбои. Эти сочетания не получают новых обещаний и не входят в приёмку этого этапа. Остаток Q-01–Q-14, форм, дизайнера, поставки runtime, IME/доступности/локализации сохраняется.
