# Spec Delta

## ADDED Requirements

### Requirement: Failed tree operation retains cleanup diagnostics
При неудачной операции дерева с сохранённым прежним состоянием SetParent SHALL возвращать исходную ошибку и все сбои очистки попытки. Паника отдельной cleanup-операции SHALL сохраняться со значением и стеком без повторного выбрасывания; очистка независимых ресурсов продолжается. Приложение SHALL продолжать работу при сохранённом прежнем нативном состоянии.

#### Scenario: Cleanup fails but old tree survives
- **WHEN** присоединение даёт ошибку E, прежнее состояние сохранено, очистка попытки даёт E1 и panic W, независимый ресурс ещё требует очистки
- **THEN** SetParent возвращает E/E1/W со стеком W, попытка независимой очистки выполняется; прежние размещение и уведомления сохранены, приложение продолжает работу

### Requirement: Unrecoverable tree operation stops application
Невозможность восстановить прежнее работоспособное нативное состояние SHALL начинать аварийную остановку. SetParent SHALL возвращать ошибку; текущий обработчик может завершиться. Новые прикладные обработчики MUST NOT запускаться, ожидающие уведомления отменяются. После выхода из callback SHALL выполняться очистка, Run возвращает исходную ошибку, сбои восстановления и очистки без выдуманной первичной паники.

#### Scenario: Rollback cannot restore old placement
- **WHEN** операция даёт E, восстановление прежнего размещения даёт R и прежнее состояние нельзя восстановить
- **THEN** приложение останавливает доставку, SetParent возвращает error, текущий вызов может закончиться; после callback выполняется очистка, Run сохраняет E/R и все её сбои

#### Scenario: Cleanup panic after fatal rollback
- **WHEN** после невозможного восстановления очистка вызывает panic W
- **THEN** W и стек сохраняются, независимая очистка продолжается; W не выбрасывается повторно и не подменяет исходную ошибку

#### Scenario: First attachment cannot restore previous state
- **WHEN** первое присоединение поддерева даёт ошибку E и восстановить прежнее работоспособное нативное состояние приложения не удаётся из-за R
- **THEN** применяется аварийная остановка: SetParent возвращает error, ожидающие уведомления и Post отменяются, новые Post отклоняются; после callback Run возвращает E/R и сбои очистки
- **AND** пригодность к повторному присоединению в этой работающей сессии не гарантируется; этот исход не является обычной ошибкой сценария Failed first attachment
