# Spec Delta

## MODIFIED Requirements

### Requirement: Transactional parent assignment
SetParent SHALL возвращать error. При обычной ошибке прежние Parent, Owner, настройки, обработчики и работоспособное размещение MUST сохраняться. Очистка частичных ресурсов SHALL предприниматься с сохранением всех сбоев. Невозможность восстановить прежнее нативное состояние SHALL быть явно исключённым аварийным исходом по application-failure, а не обычным откатом.

#### Scenario: Failed move of a visible component
- **WHEN** перенос отображаемого компонента в другой контейнер завершается обычной ошибкой, восстановление и очистка успешны
- **THEN** возвращается ошибка, компонент остаётся работоспособным у прежнего Parent со всеми настройками и обработчиками
- **AND** частичные ресурсы неуспешного переноса освобождены

#### Scenario: Failed first attachment
- **WHEN** первое присоединение настроенного компонента без Parent завершается обычной ошибкой с сохранённым прежним состоянием
- **THEN** Parent остаётся nil, Owner, настройки и обработчики сохраняются для последующей попытки

### Requirement: Fixed pre-run geometry for MVP
SetClientSize SHALL оставаться доступным только до Run. SetBounds SHALL быть доступным до Run и во время работы у живых неприсоединённых контролов, включая детей неприсоединённой панели. Размер клиентской области точный; Bounds задаёт фиксированные координаты относительно Parent и минимальные размеры. Размеры MUST быть положительными, координаты неотрицательными; нарушение вызывает panic. Автоматическое размещение не выполняется.

#### Scenario: Fixed form layout
- **WHEN** до Run задана клиентская область 400 на 180 и координаты контролов внутри неё
- **THEN** backend сохраняет заданные координаты и точный размер клиентской области в своём координатном пространстве с учётом начального масштаба; размер каждого контрола не меньше заданного и может быть увеличен нативной темой, без автоматической перестановки контролов

#### Scenario: Invalid dimensions
- **WHEN** до Run размер задан нулём или отрицательным числом либо координата отрицательна
- **THEN** setter вызывает panic как ошибку использования API

### Requirement: Fixed window size and startup scale for MVP
Главная форма MVP MUST NOT допускать пользовательское resizing. Масштаб SHALL фиксироваться при запуске; перенос между мониторами с разным DPI не входит в этот этап; во время работы изменение геометрии присоединённых контролов не поддерживается, неприсоединённые настраиваются по правилу SetBounds. Одинаковые Bounds MUST NOT трактоваться как обещание одинакового внешнего вида разных native controls.

#### Scenario: User attempts to resize
- **WHEN** пользователь пытается изменить размер главного окна штатными средствами resizing
- **THEN** пользовательское изменение размера недоступно, заданная клиентская область сохраняется при исходном масштабе

## ADDED Requirements

### Requirement: General ownership and container roles
Owner SHALL иметь общую роль Component, Parent — визуальную роль Container. Form и Panel SHALL поддерживать обе роли. Owner обычного компонента SHALL быть обязательным и неизменяемым в этом этапе; NewForm создаёт корень без Owner. Это не фиксирует навсегда политику полной библиотеки.

#### Scenario: Different owner and parent
- **WHEN** кнопка создана с Owner panelA, а Parent назначается panelB с той же корневой формой
- **THEN** Owner остаётся panelA, Parent становится panelB; прежний каскад уничтожения действует по обеим связям

#### Scenario: Invalid constructor owner
- **WHEN** конструктору обычного компонента передан пустой или уничтоженный Owner
- **THEN** возникает panic до регистрации компонента и любых нативных действий

### Requirement: Minimal nested panel
NewPanel(owner) SHALL создавать контейнер без Parent. Panel SHALL поддерживать SetParent, SetBounds, Owner, Parent, Destroy и Destroyed. Дети SHALL размещаться относительно внутренней области непосредственного Parent и обрезаться её границами. Панель MUST NOT автоматически увеличиваться ради детей; layout, прокрутка, заголовок и настраиваемая рамка не входят в этап.

#### Scenario: Nested clipping
- **WHEN** вложенная панель содержит кнопку, выходящую за внутреннюю область панели
- **THEN** координаты кнопки относительны панели, выходящая часть обрезана, панель автоматически не расширяется

#### Scenario: Panel cascade during callback
- **WHEN** обработчик ребёнка уничтожает панель с пересекающимися связями Owner и Parent
- **THEN** все участники каскада сразу логически уничтожены; повторное освобождение исключено, физическое освобождение может ждать выхода из callback

### Requirement: Dynamic logical construction and subtree attachment
Конструкторы контролов во время работы SHALL создавать только логические объекты. Связи внутри неприсоединённого поддерева SHALL настраиваться без native-создания. Присоединение к работающей форме SHALL синхронно создавать и настраивать всё поддерево до возврата nil, без ожидания paint.

#### Scenario: Prepare during Run
- **WHEN** UI-обработчик создаёт панель и её детей, настраивает свойства и связывает их без цепочки Parent до формы
- **THEN** объекты остаются логическими, настройки сохраняются без нативных ресурсов

#### Scenario: Attach prepared subtree
- **WHEN** подготовленную панель присоединяют к контейнеру работающей формы
- **THEN** до возврата nil созданы и настроены все её native-компоненты, свойства доступны немедленно; первая отрисовка не ожидается

#### Scenario: Deferred preparation before Run
- **WHEN** поддерево присоединено к форме до запуска
- **THEN** нативные компоненты создаются при Run по прежнему startup-контракту

### Requirement: Atomic subtree parent transaction
SetParent SHALL рассматривать переносимое визуальное поддерево как одну операцию. При обычной ошибке MUST сохраняться Parent корня, внутренние связи, Owner, свойства и обработчики всех потомков. Очистка ресурсов попытки и исключительный отказ восстановления SHALL подчиняться application-failure.

#### Scenario: Child creation fails
- **WHEN** панель и первая кнопка созданы при попытке присоединения, создание Edit не удалось, прежнее состояние сохранено
- **THEN** возвращается error, частичное присоединение не остаётся, выполняется очистка ресурсов попытки, подготовленное поддерево пригодно к повторной попытке

### Requirement: Parent validation precedes native changes
SetParent SHALL отклонять self-parent, присоединение к визуальному потомку, уничтоженный Parent и другую корневую форму через error до нативных действий. Корневая форма SHALL определяться цепочкой Owner. При отказе MUST сохраняться состояние и уведомления. Уничтоженный получатель SHALL вызывать panic первым.

#### Scenario: Cycle in detached tree
- **WHEN** PanelA содержит PanelB и PanelA.SetParent(PanelB) вызывается до Run либо во время работы
- **THEN** операция возвращает error без изменения дерева и нативных действий

#### Scenario: Self parent
- **WHEN** панели назначают её саму как Parent
- **THEN** операция возвращает error без изменения состояния

#### Scenario: Cross form root
- **WHEN** корни цепочек Owner компонента и нового контейнера различаются, включая неприсоединённые деревья
- **THEN** перенос возвращает error; несколько работающих форм и межформенные переносы не поддерживаются

#### Scenario: Destroyed target
- **WHEN** живой компонент присоединяют к логически уничтоженному контейнеру
- **THEN** возвращается error без изменений, даже если физическое освобождение контейнера ещё не выполнено

#### Scenario: Destroyed receiver priority
- **WHEN** уничтоженному компоненту передают недопустимый Parent
- **THEN** возникает panic получателя до проверок Parent и любых нативных действий

### Requirement: Same parent assignment is inert
SetParent с текущим Parent SHALL возвращать nil без native-пересоздания, событий, изменения уведомлений или базы сравнения. Это SHALL включать nil у уже не имеющего Parent компонента. Проверка уничтожения и требование UI-потока во время работы сохраняются.

#### Scenario: Repeat current parent
- **WHEN** живому компоненту на допустимом потоке повторно назначают текущего Parent
- **THEN** возвращается nil, состояние, уведомления и native-объекты не меняются

#### Scenario: Repeat nil
- **WHEN** живой компонент уже без Parent и SetParent(nil) вызван на допустимом потоке
- **THEN** вызов успешен и ничего не меняет

### Requirement: Detached geometry while running
Во время работы SetBounds SHALL разрешать настройку живого неприсоединённого контрола, включая потомка неприсоединённой панели и ранее отсоединённый контрол. Изменение Bounds присоединённого контрола не поддерживается в этом этапе. Минимальные размеры темы и прежняя валидация значений сохраняются.

#### Scenario: Configure detached child
- **WHEN** после запуска вызывают SetBounds ребёнка панели, цепочка Parent которой не достигает формы
- **THEN** новая геометрия сохраняется и применяется при присоединении

#### Scenario: Configure after detachment
- **WHEN** ранее отображённую панель отсоединили и настраивают Bounds её ребёнка
- **THEN** настройка разрешена несмотря на прежнее native-создание

### Requirement: Direct move preserves input state
При прямом переносе между присоединёнными контейнерами одной формы Golphi SHALL сохранять фокус внутри поддерева, курсор и выделение Edit; перенос MUST NOT забирать внешний фокус. При обычной ошибке SHALL сохраняться прежнее состояние ввода. Невозможность обеспечить гарантии SHALL приводить к отказу с откатом либо аварийному исходу по application-failure.

#### Scenario: Focused edit moves
- **WHEN** Edit с курсором и выделением переносится между присоединёнными панелями
- **THEN** фокус, курсор и выделение сохранены, независимо от внутреннего пересоздания peer

#### Scenario: External focus stays
- **WHEN** фокус вне переносимого поддерева
- **THEN** перенос не переводит фокус внутрь поддерева

#### Scenario: Move fails with input state
- **WHEN** перенос завершился обычной ошибкой
- **THEN** прежнее размещение, фокус, курсор и выделение сохранены

### Requirement: Detach preserves selection without restoring focus
Явное отсоединение и повторное присоединение SHALL сохранять курсор и выделение Edit при неизменном тексте. Присоединение MUST NOT автоматически возвращать или захватывать фокус. После отсоединения сфокусированного поддерева конкретный новый получатель фокуса не гарантируется и выбирается native-системой.

#### Scenario: Reattach unchanged edit
- **WHEN** поддерево с выделением Edit отсоединяют и присоединяют без изменения текста
- **THEN** курсор и выделение восстановлены без автоматического возврата фокуса

### Requirement: Detached text edit resets selection
Реальное изменение текста отсоединённого Edit через SetText SHALL снимать выделение и ставить курсор в конец нового текста. Присваивание того же текста MUST сохранять курсор и выделение. Это правило MUST NOT менять контракт SetText присоединённого поля.

#### Scenario: Change detached text
- **WHEN** текст отсоединённого Edit меняют с А на Б
- **THEN** выделение снято, курсор в конце Б; изменение и последующее присоединение тихие и не захватывают фокус

#### Scenario: Assign same detached text
- **WHEN** отсоединённому Edit присваивают его текущий текст
- **THEN** курсор и выделение сохраняются
