# Proposal

## Why

Основные контракты Golphi оставляли открытыми поведение уничтоженного объекта и уведомлений при изменении обработчика или жизненного состояния. Согласованные решения закрывают эту часть Q-05/Q-06 и задают диагностируемую остановку приложения при панике обработчика.

## What Changes

- Определить немедленное логическое уничтожение через Destroy(), безопасный повторный вызов и Destroyed() bool; обычные операции уничтоженного объекта вызывают panic.
- Разрешить отложенное физическое освобождение до выхода из callback, сохранив существующий каскад уничтожения.
- Отменять не начатые уведомления уничтоженных компонентов; текущий обработчик продолжает выполнение.
- Отменять ожидающие OnChange всего поддерева при успешном отсоединении и сохранять их при ошибке SetParent.
- Перенаправлять ожидающий OnChange текущему обработчику при замене; SetOnChange(nil) отменяет ожидающее уведомление и накопление внутри обработчика без восстановления при последующем назначении.
- После отключения начинать сравнение заново: новое изменение после назначения снова создаёт уведомление, даже если текст совпал со входом в старый обработчик.
- При панике обработчика останавливать прикладные события, после выхода из callback очищать ресурсы и возвращать из Form.Run() ошибку с исходным значением паники и стеком.

## Capabilities

### New Capabilities

- `application-failure`: остановка доставки прикладных событий и диагностика паники обработчика через Form.Run().

### Modified Capabilities

- `component-lifecycle`: логическое уничтожение, безопасные Destroy/Destroyed и panic при остальных обращениях.
- `component-events`: отмена, замена адресата, сброс накопления и базы сравнения OnChange.

## Impact

Изменение продолжает E0: при apply обновляются документация и проектные трассировки. Runtime, backend и FFI здесь не реализуются. Основные спецификации получат дельты при отдельной синхронизации/архивации; исторический архив define-component-contract не переписывается.

Post, ошибки очистки, обычная остановка, оставшиеся вопросы Q-01–Q-14 и неподтверждённые детали API остаются открытыми. Весь E0 не объявляется завершённым. Процесс дальнейшей разработки сохраняется по docs/development.md: ветки от develop без worktree, Subagent Driven Development, параллельные независимые задачи, commit/push по этапам и итоговый PR.
