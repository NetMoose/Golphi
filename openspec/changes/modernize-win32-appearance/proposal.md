# Proposal

## Why

Текущие Win32-контролы Golphi выглядят классическими: приложение не поставляет манифест visual styles, а backend не назначает системный UI-шрифт. WIN-01 из backlog выделяет это улучшение в самостоятельный этап после динамического дерева, сохраняя нативное поведение и сборку без C toolchain.

## What Changes

- Основной способ включения visual styles — явный XML-манифест приложения с зависимостью Common Controls v6, встроенный в EXE через `.syso` пакета `main`.
- Подготовка ресурсов выполняется `go-winres` с закреплённой версией, проверенной на Linux и Windows с `CGO_ENABLED=0`; существующий манифест приложения дополняется, второй не навязывается.
- Без манифеста запуск остаётся разрешённым с классическим оформлением и системным шрифтом; visual styles гарантируются только для корректно подготовленного приложения в принятом окружении с включёнными стилями Windows.
- Win32 backend получает `lfMessageFont` для DPI запуска, создаёт один общий `HFONT` и назначает его Button/Edit/Label, включая динамически созданные и пересозданные контролы.
- Backend владеет шрифтом до завершения работы использующих его нативных контролов; ошибки запуска и очистки следуют существующим контрактам с уточнением зависимости контролов от шрифта.
- Сохраняются ручная геометрия и минимальные размеры `SetBounds`: без подбора ширины по содержимому, автоматической раскладки и исправления пересечений.
- Добавляются проверочный пример, воспроизводимая подготовка ресурсов и фактическая Windows 11/amd64 приёмка на 100% и 150% с доказательствами оформления, текста, clipping и сохранения взаимодействий.

## Capabilities

### New Capabilities

- `windows-native-appearance`: подключение visual styles пользовательским приложением, системный шрифт и его ресурсы, геометрия и проверяемые границы Windows-оформления.

### Modified Capabilities

Нет. `native-ui-runtime` и `application-failure` остаются базовыми контрактами запуска и диагностики; новая спецификация добавляет узкие требования WIN-01, не выбирая общую политику зависимой очистки.

## Impact

Целевые области реализации: `internal/backend/win32`, Windows native/fault-injection tests, примеры, build/verification scripts и документация. Публичный Go API не расширяется; GTK4-оформление не меняется. `go-winres` — инструмент подготовки ресурсов, а не runtime-зависимость Golphi. GUI-примеры собираются с `-ldflags="-H windowsgui"`, тестовые EXE остаются консольными.

Разработка: ветка от актуальной `develop`, без worktree; Subagent Driven Development, независимые задачи параллельно при возможности, Git у координатора; review и commit/push по этапам, итоговый PR в `develop`. Реализация начинается отдельным `openspec-apply-change`. DOC-01 и остальные открытые вопросы не входят в этот этап.
