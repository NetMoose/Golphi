# Spec Delta

## ADDED Requirements

### Requirement: MVP startup error retains cleanup diagnostics
При ошибке запуска MVP Run SHALL прекращать запуск и предпринимать очистку созданных ресурсов. После попыток Run SHALL возвращать ненулевую ошибку, сохраняющую исходную ошибку запуска и все собранные сбои очистки. Приём Post MUST NOT открываться. Ошибки загрузки библиотеки, обязательного символа, инициализации backend и создания native-компонента SHALL обрабатываться этим правилом.

#### Scenario: Partial startup failure
- **WHEN** часть native-компонентов создана, следующий создать не удалось, а очистка дала ошибки E1/E2 и панику W
- **THEN** дальнейший запуск прекращён, очистка созданного предпринята, Run возвращает исходную ошибку и E1/E2/W со стеком W; Post не принимается

#### Scenario: Backend cannot initialize
- **WHEN** библиотека или обязательный символ отсутствует либо графическое окружение не позволяет инициализировать backend
- **THEN** Run возвращает ошибку исходного этапа и сбои очистки, если они возникли, без открытия приёма Post

### Requirement: Normal MVP closure reports cleanup failures
После обычного закрытия MVP и завершения попыток очистки Run SHALL возвращать nil при отсутствии сбоев либо ненулевую ошибку со всеми собранными ошибками и значениями/стеками перехваченных паник очистки. Перехваченные паники MUST NOT повторно выбрасываться наружу; первоначальная прикладная паника для такого результата не требуется.

#### Scenario: Normal closure with several cleanup failures
- **WHEN** при обычном закрытии очистка дала E1, E2 и panic(W) со стеком S
- **THEN** Run возвращает ошибку с E1/E2/W/S без повторного выбрасывания W и без выдуманной первичной паники

### Requirement: Cleanup without primary panic continues independent operations
При очистке после ошибки запуска или обычного закрытия MVP ошибка операции SHALL сохраняться и MUST NOT прекращать попытки остальных независимых операций. Паника SHALL перехватываться на границе отдельной операции с сохранением значения и стека; попытки независимой очистки SHALL продолжаться. Порядок зависимых ресурсов, повторы и тайм-ауты этим не выбираются.

#### Scenario: Error and panic do not skip independent resources
- **WHEN** при обычном закрытии либо ошибке запуска очистка А даёт ошибку, очистка независимого Б вызывает панику, а В ещё требует независимой очистки
- **THEN** оба сбоя сохраняются и попытка очистить В выполняется; успешное освобождение всех ресурсов не обещается

### Requirement: Cleanup failures do not resume a stopping MVP
Сбой очистки при обычном закрытии или ошибке запуска MVP MUST NOT возобновлять приложение, открывать Post или восстанавливать отменённые задачи и уведомления. Новые прикладные обработчики MUST NOT запускаться. Необходимые внутренние действия для выхода и очистки SHALL продолжаться.

#### Scenario: Failed cleanup leaves delivery stopped
- **WHEN** очистка при обычном закрытии завершилась с ошибкой
- **THEN** отменённые уведомления и Post не запускаются, новые Post отклоняются, Run возвращает ошибку
